# Фича: «Поручить агенту» — промт для Claude Code / Codex из задачи PULSE

Статус: спецификация для разработки (штурм 03.11.2026). Версия 1.2 — этап 1 (MVP) выпущен в 2.0.8 (04.11.2026),
этап 2 сделан 04.11.2026; что проверено и что решено по ходу — в разделах «Запуск», «Связь задачи и сессии», «Этапы»
и «Развилки».

## Зачем

Часть задач директора уже сейчас делают агенты: сводки, расчёты, ресёрч, постановки, черновики регламентов.
Директор каждый раз сам пишет агенту длинный промт и вспоминает контекст: что решили на встрече, какие файлы
нужны, как похожую задачу делали в прошлый раз. Всё это PULSE уже знает:

- **контекст задачи** — откуда она (встреча с цитатой и `[чч:мм:сс]`, сообщение), срок, проект, связи «ждёт»,
  решения из базы знаний, люди, документы из индекса;
- **контекст агентской работы** — «Офис» читает журналы сессий Claude Code в папках из Настройки → Офис: первый
  промт и все следующие реплики человека, какие файлы сессия читала и создала, навыки, субагенты, итог.

Значит, PULSE может сам собрать подробный промт, а директор только проверит его и:
**а)** скопирует и отнесёт агенту, **б)** одним нажатием откроет новую сессию в Claude Code или Codex с этим промтом.

Принцип PULSE сохраняется: сам PULSE агента не запускает, последнее нажатие делает человек.

## Как это выглядит

1. В окне задачи (и в меню «…» карточки на доске) есть кнопка **«Поручить агенту»**. Подсказка «Можно поручить
   агенту» появляется у задач, похожих на агентские: сводка, таблица, расчёт, ресёрч, черновик, регламент,
   постановка, анализ. Кнопка при этом доступна у любой задачи.
2. Открывается панель «Поручить агенту»:
   - **Где работать**: папка и проект. По умолчанию PULSE подставляет папку, где делали похожие задачи, иначе — папку проекта задачи,
     иначе первую из Настройки → Офис. Выпадающий список — папки и их проекты (папки первого уровня, как в «Офисе»).
   - **Кто**: Claude или Codex. По умолчанию — помощник, выбранный в PULSE.
   - Кнопка **«Собрать промт»**. Фоновый запуск длится 30–90 секунд, его шаги видны, как в «Спросить Claude».
3. Готовый промт показывается редактируемым текстом. Под ним:
   - **Файлы** — список с галочками и причиной: «использовали в 2 похожих сессиях», «найден по словам
     „KPI калькулятор“», «из встречи 30.10». Снятая галочка убирает файл из промта.
   - **Похожие поручения** — 1–3 прошлые сессии: название, когда, сколько реплик понадобилось, что получилось;
     ссылка «Открыть в Claude».
   - Поле **«Что поправить»** и кнопка **«Пересобрать»** («добавь про прогноз Q4», «без расчёта маржи»).
4. Кнопки внизу: **«Копировать промт»**, **«Открыть в Claude»**, **«Открыть в Codex»**.
5. После запуска на задаче появляется блок **«Агент»** со статусом сессии: работает, ждёт вашего ответа или
   готово. Метка с роботом видна и на карточке доски. В блоке — ссылка на сессию и файлы, которые она создала.
   Сессия видна и в «Офисе», с пометкой «по задаче «…»».
6. Когда сессия закончила работу (статус приложения `completed` / `review_ready`), PULSE предлагает:
   «Закрыть задачу «…» — агент сделал: <файлы>». Это обычное предложение `task.done` с кнопкой «Закрыть задачу».

## Что входит в промт

Шаблон (навык `agent-brief` может менять порядок и опускать пустые разделы):

```
# Задача: <заголовок>
PULSE: задача #<id>          ← служебная строка, по ней PULSE находит сессию

## Что нужно получить
<результат и критерий готовности — из what/title, уточнённый по источнику>
Срок: ДД.ММ. Для кого: <кому обещано>.

## Контекст
- Откуда задача: встреча «…» ДД.ММ [чч:мм:сс] — «цитата»; сообщение в чате «…» ДД.ММ — «цитата».
- Проект «…»: зачем он и что в нём уже сделано (2–3 строки).
- Решения, которые нельзя нарушать: … (база знаний, с датой и источником).
- Ждём / нас ждут: …

## Файлы
- <абсолютный путь> — зачем (что в нём, какой лист / слайд)
- …

## Как такое уже делали
- «<название сессии>» ДД.ММ: просили <суть первого промта>; использовали <файлы>; получилось <файлы / итог>.
  Пришлось уточнять: <что человек дописал следующими репликами — этого не хватало в первом промте>.

## Как сделать
<шаги, если они понятны из похожих сессий; формат результата; куда положить файл>

## Если неясно
<1–3 вопроса, которые стоит задать до начала, а не угадывать>
```

Правила для навыка:
- Писать как ставит задачи сам пользователь. Его прошлые первые промты — образец словаря и степени
  детальности, а не текст для копирования.
- Только факты из источников. Если данных нет, промт так и говорит: «прогноза в данных нет — спроси».
- Личные (нерабочие) переписки не цитировать (правило 9 CLAUDE.md). Секреты, токены и пути в `secrets/` в промт
  не попадают.
- Файлы — абсолютными путями, только существующие.
- Длина — сколько нужно. Если промт получился длиннее лимита ссылки, полный текст уходит в файл (см. «Запуск»).

## Запуск

### Claude (приложение Claude, вкладка Code)

Проверено в коде приложения Claude (macOS, ноябрь 2026): обработчик ссылок понимает
`claude://code/new?q=<промт>&folder=<путь>&file=<путь>`:
- `q` (или `prompt`) — текст в поле ввода новой сессии, обрезается до ~14 336 символов;
- `folder` (можно несколько) — папка сессии;
- `file` (можно несколько) — приложенные файлы.

**Проверено руками на Mac (приложение Claude 4.4212, 03.11.2026):**
- `q` только **вставляет** текст в поле ввода новой сессии, сам не отправляет: сессия не создаётся, пока человек
  не нажмёт Enter. Кнопка «Открыть и запустить» не нужна.
- `folder` выбирает папку сессии. Папку внутри `…/.claude/worktrees/<имя>/…` приложение заменяет корнем репозитория
  и спрашивает «Доверять этому рабочему пространству?» — это видно на демо-стенде (он лежит в рабочей копии ветки);
  для обычных папок проектов этого нет.
- `file=` для `code/new` приложение **не прикладывает**: в коде он идёт только в счётчик (`has_file`), в новую сессию
  не передаётся (прикладываются файлы только у `cowork/new`). Файл вне папки сессии, значит, тоже не приложится.
  Поэтому у длинного промта путь к файлу брифа написан прямо в коротком поручении в `q`; `file=` PULSE всё равно
  добавляет — на случай, если приложение начнёт его понимать. Агент читает бриф по абсолютному пути (Claude Code
  может спросить разрешение на чтение вне папки сессии).
- Длина: `open` передаёт ссылку в 65 КБ (12 000 символов кириллицы в `q`) целиком, поле ввода получает весь текст.
- Windows не проверено: там ссылка открывается `os.startfile`, и промт длиннее ~2000 символов в ссылке PULSE
  на всякий случай отдаёт файлом (короткое поручение с путём к брифу).

Так же «Офис» уже открывает существующие сессии через `claude://code/continue?session=<local_…>`.

Порядок:
1. Полный промт всегда сохраняется в `data/agent-briefs/<id задачи>-<короткое имя>.md` — для истории и для длинных промтов.
2. Если промт помещается в ~12 000 символов, он целиком идёт в `q`. Иначе в `q` — короткое поручение
   («Задача из PULSE #<id>. Полный бриф — в файле <абсолютный путь>, прочитай его целиком и действуй по нему»),
   и путь к брифу ещё раз — в `file` (сейчас приложение его не прикладывает, см. выше).
3. Ссылка открывается системно: `open` на Mac, `os.startfile` или `start` на Windows. Отправку промта (Enter)
   делает человек в приложении.

**Проверить при разработке:** отправляет ли `q` промт сам или только вставляет его в поле. Нужно, чтобы только вставлял;
если отправляет сам, это допустимо только после явной кнопки «Открыть и запустить». Ещё проверить: как `file=` прикладывает файл
вне папки сессии; работает ли ссылка на Windows; нет ли ограничения длины URL у `open`.

### Codex (приложение ChatGPT)

ChatGPT.app регистрирует схему `codex://`, но маршрута «новый тред с промтом в папке» в коде приложения не нашлось
(есть `codex://threads/…`, `codex://launch`, `codex://settings`). План:
1. Если при разработке найдётся рабочая ссылка с промтом и папкой — использовать её.
2. Иначе «Открыть в Codex» открывает Терминал с интерактивным Codex CLI в папке и промтом:
   `codex -C "<папка>" "<короткое поручение со ссылкой на файл брифа>"` (на Mac — через `osascript`
   `tell application "Terminal" to do script`, на Windows — новое окно PowerShell). Путь к codex — `codex.find()`.
3. Запасной вариант всегда есть: «Копировать промт».

### Не в этой версии
Фоновый запуск агента без человека (`claude -p` в чужой папке) не делаем: там другие права и нет присмотра.
Задел на потом: в приложении есть `claude://resume?session=<uuid>` — импорт CLI-сессии в приложение.

## Связь задачи и сессии

- Новая сессия находится по служебной строке `PULSE: задача #<id>` в первом промте: «Офис» уже читает первый промт
  каждой сессии в папках (`opsdash/office.py`, `_feed` → `s["prompt"]`). Если промт ушёл файлом, PULSE ищет
  в журнале строку или имя файла брифа.
- Связь хранится в таблице (см. «Данные»). Статус берётся у «Офиса»: `working` / `waiting` / `blocked` / `rest`
  плюс статус приложения (`desktop_sessions()`: completed, review_ready, blocked + needs).
- Файлы, которые сессия создала (`s["written"]`), показываются в задаче как результат: «Открыть», «Показать в Finder».
- Сессия «готово» → предложение `task.done` с доводом «агент сделал: …» и ссылками на файлы. Сам PULSE задачу не закрывает,
  кроме режима «Автономия», как и сейчас.

Сделано в этапе 2:
- Задание `agents-watch` (`agents.check`, вручную — `./ops agents watch`) раз в минуту, пока есть поручения, открытые в Claude
  за последние 14 дней по открытым задачам. Ищет в папке поручения (без папки — во всех папках «Офиса») сессию, начатую не раньше
  чем за 2 минуты до «Открыть в Claude», с `PULSE: задача #<id>` (не `#<id>0`) или именем файла брифа в первой реплике; берёт самую
  свежую. Найденная сессия сразу попадает в индекс опыта, связь — `task_agents.session_id`, `desktop_id`, `state='linked'`.
- Состояние сессии считается на лету, как в «Офисе»: по журналу (`office._state`) плюс итог приложения (`desktop_sessions()`:
  `completed` / `review_ready` → «готово», `needs` → что нужно от вас). Приложение забыло сессию — берём его последнюю оценку
  из индекса. Для окна задачи и меток на карточках — `agents.marks()` с кэшем на 5 секунд.
- Готово → `proposals.propose_task_done(label="Закрыть задачу «…» — агент сделал: <файлы>", source_ref="agent:<сессия>")`,
  один раз (`state='proposed'`); у предложения ссылка «Сессия агента» (`claude://code/continue`). Созданные файлы —
  `task_agents.result_files`, открываются через `/office/open` (только файлы из папок «Офиса»).
- В «Офисе» — `s["task"]` у сессии и строка «По задаче «…»».
- Открыть панель «Поручить агенту» с любой страницы: элемент с `data-agent-open="<id задачи>"` (обработчик в `static/agents.js`,
  он подключён на всех страницах) или `?agent=<id задачи>` в адресе любой страницы (`/commitments?task=18&agent=18`, `/?agent=18`);
  без скриптов — `/agents?task=<id>`.

## Обучение на прошлых поручениях

Здесь и есть «второй контекст» — как такие задачи решаются агентами:
- **Индекс агентских сессий.** Для каждой сессии в папках «Офиса» (и для Codex — `~/.codex/sessions/**/rollout-*.jsonl`,
  формат проверить) хранится: папка и проект, название, первый промт целиком, следующие реплики человека (первые
  ~10, по 500 символов), прочитанные и созданные файлы, навыки, субагенты, длительность, число реплик, итог
  (последний ответ агента коротко и статус приложения). Читается инкрементально, как в `office._session`;
  фоновые запуски самого PULSE пропускаются.
- **Похожие сессии** ищутся полнотекстом (FTS5, как `docs_fts`) по заголовку и тексту задачи, по проекту и по
  файлам, общим с задачей.
- **Чего не хватило.** Реплики человека после первого промта («смотри ещё файл X», «нет, считай без НДС») —
  сигнал, чего не было в постановке. Навык выносит их в «Пришлось уточнять» и добавляет в новый промт сразу.
- **Пара бриф → результат.** Сессия, запущенная из PULSE, сохраняет связь «бриф → число реплик до результата →
  файлы». Это будущие образцы: брифы, после которых хватило 1–2 реплик, — лучшие примеры.

  Секреты (`secrets/`, `.env`, `.ssh`, «token», «password»), служебное Claude Code (`~/.claude`) и временное
  (`/tmp`) в индекс не попадают. Первый разбор 510 сессий (2,5 ГБ журналов) — 14 с, повторный — 1 с.
- Таблица `task_agents` — поручения: commitment_id, brief_path, engine, folder, created, launched_at,

- `opsdash/agents.py` — индекс (переиспользовать разбор журналов из `office.py`, не дублировать; при необходимости

  Сделано: `brief-save` и `context` принимают номер поручения (`task_agents.id`), а не задачи; `./ops agents context <id>` —
  всё для навыка одним текстом (задача и источник с местом в расшифровке, паспорт и свежие файлы папки, похожие сессии,
  файлы-кандидаты с причинами, решения, прошлый промт и «что поправить»); `./ops agents index` — дочитать журналы.
- Навык `.claude/skills/agent-brief/SKILL.md` — сборка промта по шаблону выше: `./ops commitments show`,
  источник (встреча или сообщения), `./ops projects show`, `./ops kb search`, `./ops docs search`, `./ops agents similar`
  и `show` по 1–3 лучшим. Модель — как у «Спросить» (opus по умолчанию). Работает и через Codex (`codex.py`).
- Задание `agent-brief` в очереди чата: короткое, по кнопке, со стримингом шагов, как «Спросить Claude».
- Веб: блок в окне задачи (`templates/tasks.html` и связанные), панель поручения, метка на карточке, пометка
  в «Офисе». API: собрать, пересобрать, сохранить правку, ссылка запуска, статус.
- Настройки → Офис: «Папка по умолчанию для поручений» и при желании соответствие «проект PULSE → папка».
  Сделано в этапе 2: «Папка по умолчанию для поручений агенту» (`office.agent_folder`); порядок — где делали похожие задачи,
  проект с названием проекта задачи, эта папка, первая папка «Офиса». Соответствие «проект → папка» не делали.

## Безопасность и правила

- Сборка промта — обычный фоновый запуск PULSE с теми же правами: читает базу, встречи, документы и журналы
  сессий, пишет только в `data/`.
- Журналы Claude Code PULSE только читает, как сейчас «Офис».
- Запуск агента — только нажатием человека; промт открывается, но не отправляется сам.
- В промт не попадают `secrets/`, токены и личные переписки.

## Готово, когда

- У задачи из встречи «Собрать промт» за ≤ 90 с даёт бриф со всеми разделами. В брифе — цитата из встречи
  со временем, ≥ 1 файл с причиной и ≥ 1 похожая сессия, если она есть в индексе.
- «Открыть в Claude» открывает новую сессию в нужной папке с промтом в поле ввода (Mac; Windows — проверено или явно
  описано ограничение).
- Запущенная сессия находится и показывается на задаче в течение минуты; файлы, которые она создала, видны в задаче.
- Тесты: разбор журналов в индекс (фикстуры jsonl), поиск похожих, сборка ссылки (длинный промт → файл), поиск
  сессии по служебной строке.
- Запись в `docs/06-история-изменений.md` и раздел в `docs/03-как-пользоваться.md`.

## Развилки (по умолчанию — первый вариант)

1. Куда агент кладёт результат: (а) в папку проекта, где идёт сессия, а PULSE показывает ссылки; (б) копию в `data/`.
   **Этап 1: (а)** — навык просит класть результат в папку проекта.
2. Подсказка «Можно поручить агенту»: (а) только меткой; (б) ещё и строкой в утреннем дайджесте.
   **Этап 1: (а)** — кнопка «Поручить агенту» в окне задачи подсвечена и с подсказкой у похожих задач.
3. Проверка промта: (а) всегда показываем перед запуском; (б) для задач из «доверенного» проекта — сразу «Открыть».
   **Этап 1: (а)** — и в самом приложении промт только встаёт в поле ввода.

Решено по ходу этапа 1:
- Одно поручение на задачу: «Пересобрать» обновляет его же, правки директора навык видит (прошлый промт — в контексте).
- Панель — отдельное окно поверх окна задачи (кусочек `/agents?task=<id>&part=1`), и та же страница `/agents?task=<id>`
  без скриптов; уведомление «Промт для агента готов» ведёт на неё. В меню «…» карточки доски кнопки нет — только в окне задачи.
- «Кто»: Codex — промт пишется для Codex, вместо «Открыть в Claude» — подсказка скопировать (открытие в Codex — этап 3).
  Собирает промт помощник, выбранный в PULSE (Claude или ChatGPT), как и все фоновые задания.
- Сборке промта (задание `agent-brief`) Claude получает папки «Офиса» на чтение (`--add-dir`), писать — по-прежнему только в `data/`.
