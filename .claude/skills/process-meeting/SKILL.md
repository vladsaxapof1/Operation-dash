# Разбор встречи

Вход: id встречи. Папка `data/meetings/<id>/` содержит `meta.json` (время, встреча
календаря с участниками) и `transcript.md` (реплики с отметками времени; спикеры —
«Спикер 1…N» или имена, если это готовая расшифровка).

## Шаги

1. **Прочитай** `meta.json` и `transcript.md` целиком.
2. **Собери контекст** (по одной команде, без конвейеров):
   - `./ops overview` — имя директора и текущие обещания;
   - `./ops people list`;
   - `./ops commitments list` — открытые обещания (чтобы заметить выполненные, связать новые с ними и не дублировать);
   - `./ops kaiten targets` и `./ops kaiten cards --limit 150` — куда создавать и что уже есть.
   - если обсуждали документ, цифры или прошлые решения — `./ops docs search "<тема>"`: сверь с презентациями
     и таблицами, в summary.md укажи файл (например, «как в «QBR Q3 2026 — Коммерция», слайд 7»).
3. **Определи, кто есть кто.**
   - **Подписанных по голосу не оспаривай.** Строка шапки «Вы в записи: <Имя> = Спикер N (…)» —
     это директор, «Узнаны: Никита = Спикер 2 (…); …» — люди из справочника; в репликах у них
     уже стоят имена. Это проверено по голосу или самим директором.
     Остальных определяй среди оставшихся спикеров.
   - **Не считай, что поручения раздаёт директор.** Директора часто зовут, чтобы поставить
     задачу ему самому. Кто есть кто — по фактам:
     обращения по имени («Дима, что у тебя?» → отвечает Дима);
     организатор встречи из `meta.json` (`event.organizer`) — обычно тот, кто позвал и ведёт;
     кто спрашивает «сколько тебе нужно / когда сделаешь» — ставит задачу,
     кто отвечает «сделаю / минут 15» — исполнитель;
     кто подробно объясняет свою часть работы — скорее всего, её и делает.
   - **Не уверен, кто из спикеров директор, — не гадай.** Пиши «Спикер 2 (вероятно, Пётр)»;
     обещания и карточки, где от этого зависит, кто исполнитель, не создавай — опиши их
     в summary.md как «нужно уточнить», а в уведомлении попроси открыть встречу и нажать
     «Это я» у своего спикера.
   - **Запиши догадку по каждому неподписанному спикеру, о котором есть факты** (кроме директора —
     его директор отмечает сам): `./ops meetings guess <id> --speaker "Спикер 3" --name "Пётр Иванов" --why "обращаются по имени [00:12:03]"`.
     Имя — как в справочнике людей. На странице встречи директор подтвердит одним нажатием, и PULSE
     запомнит голос: в следующих записях этот человек будет подписан сам.
   - Новых людей и новые написания имён добавь: `./ops people set --name "Пётр Иванов" --alias "Петя"`.
4. **Напиши `data/meetings/<id>/summary.md`** по шаблону ниже. Отметки времени `[чч:мм:сс]`
   бери из расшифровки — по ним директор найдёт место в записи.
5. **Обещания.** Каждое явное обещание с исполнителем:
   `./ops commitments add --direction mine|to_me|other --who "…" --whom "…" --title "…" --what "…" --due YYYY-MM-DD --source meeting:<id> --quote "[чч:мм:сс] дословно"`.
   `--title` — заголовок карточки, 2–6 слов («Прогноз по ключевым клиентам»); подробности — в `--what`.
   В таблице «Задачи» summary.md пиши «Что» близко к заголовку и сути обещания: по совпадению PULSE
   ставит у строки ссылку на задачу.
   - **Часть другой задачи.** Если поручение — часть уже открытой задачи (директор обещала Тимуру
     недельный отчёт, а на этой встрече просит Петра собрать выгрузку) — добавь `--parent <id той задачи>`.
     Основная задача остаётся на директоре (отвечать Тимуру всё равно ей), на доске будет видно
     «Я + Пётр → Тимур». Связать уже записанную — `./ops commitments set <id> --parent <id>`.
   - **Выполнено.** Если встреча показывает, что открытая задача сделана (результат показали, прислали,
     обсуждают как готовое), — не закрывай сам, а предложи директору:
     `./ops propose done --commitment <id> --reason "<что на встрече показывает, что сделано>" --quote "[чч:мм:сс] дословно" --source meeting:<id> --batch meeting:<id>`.
     Она подтвердит кнопкой «Да». Сам (`./ops commitments set <id> --status done --note "встреча <id>"`) —
     только если директор на встрече прямо сказала «отметь, закрой». Выполненная подзадача ещё не значит,
     что выполнена основная: её предлагай закрыть, только если результат передан тому, кому обещан.
5а. **База знаний.** Каждое решение из раздела «Решения» —
   `./ops kb add --kind decision --title "<суть-вывод одной строкой>" --details "почему, цифры" --date <дата встречи> --project "<тема>" --people "Имя, Имя" --source meeting:<id> --quote "[чч:мм:сс] дословно"`.
   Сначала `./ops kb search "<тема>"`: если прежнее решение по тому же вопросу есть — не дублируй;
   если новое его меняет, напиши в summary.md «меняет решение от ДД.ММ «…»» и упомяни в уведомлении
   (статус старой записи не трогай — решает директор). Прозвучавший урок («больше так не делаем», «ошиблись в расчёте»)
   или удачу («это сработало, повторяем») добавь с `--kind lesson|win --proposed`.
6. **Карточки Kaiten.** Для конкретных поручений коллегам (и директору — если она
   сказала «поставлю себе задачу»):
   - проверь дубль: `./ops kaiten cards --search "<ключевое слово>"`;
   - нет карточки → `./ops propose card --title "…" --description "…" --responsible "…" --due YYYY-MM-DD --target "…" --commitment <id обещания> --batch meeting:<id> --source meeting:<id> --reason "договорились на встрече"`;
   - карточка есть, но изменился срок/исполнитель → `./ops propose update --card <id> --due … --batch meeting:<id>`;
   - по карточке прозвучал важный статус → `./ops propose comment --card <id> --text "По встрече ДД.ММ: …" --batch meeting:<id>`.
   Если `propose` вернул ошибку про направления — не страшно: задачи останутся в
   summary.md и в обещаниях, упомяни это в уведомлении.
7. **Сохрани итог:**
   `./ops meetings set <id> --title "<понятное название>" --headline "<главное одной строкой>" --participants "Имя, Имя" --status processed`.
8. **Уведоми директора:**
   `./ops notify --kind meeting --batch meeting:<id> "<b>Разобрала встречу «…»</b>\n<главное в 1–2 строках>\n\nРешений: N · задач: M · ваших договорённостей: K"`.
   Если предложила закрыть выполненные задачи — добавь «Похоже, выполнены: L — подтвердите».
   Если ей нужно что-то сделать срочно по итогам — добавь строку «⚠ …».
   Если записал догадки о спикерах — добавь строку «Проверьте, кто говорит: <a href="http://localhost:8765/meetings/<id>#who">открыть встречу</a>».

## Шаблон summary.md

```markdown
# <Название встречи>

**Дата:** ДД.ММ.ГГГГ ЧЧ:ММ · **Длительность:** N мин · **Участники:** …

## Коротко
2–4 предложения: о чём договорились и что изменилось.

## Решения
1. … [чч:мм:сс]

## Задачи
| Что | Кто | Срок | Kaiten |
|---|---|---|---|
| … | … | ДД.ММ | предложено / #id / — |

## Договорённости
- **<Директор> обещала:** … — до ДД.ММ [чч:мм:сс]
- **<Имя> обещал(а) <директору>:** … [чч:мм:сс]

## Открытые вопросы
- … (кто должен решить)

## Связь с текущими задачами
- #id «…» — что изменилось

## Кто есть кто в записи
- Спикер 1 — <Имя> (по голосу / отмечено директором / уверенно: <по каким фактам> / вероятно)
  Каждому неподписанному спикеру с именем здесь — команда `./ops meetings guess` (шаг 3).
```

Пустые разделы удаляй. Не пересказывай встречу целиком — директор хочет за минуту
понять итог. Если запись не встреча (тишина, тест, обрывок) — так и напиши в
summary.md, поставь статус processed и не создавай предложений.
