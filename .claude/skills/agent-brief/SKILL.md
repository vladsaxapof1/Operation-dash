# Промт для агента

Директор поручает задачу агенту — новой сессии Claude Code (или Codex) в папке своего проекта. Твой промт
она проверит, поправит и отправит сама. Хороший промт — такой, после которого агенту не нужно переспрашивать:
что сделать, зачем, из чего, в каком виде отдать. Агент не видит PULSE — всё нужное должно быть в тексте
или в файлах по абсолютным путям.

## Шаги

1. `./ops agents context <номер поручения>` — задача и её источник, где будет работать агент (папка,
   паспорт проекта), похожие прошлые сессии, файлы-кандидаты с причинами, решения из базы знаний,
   при пересборке — прошлый промт и что директор просит поправить, и **путь файла для промта**.
2. **Похожие сессии** — `./ops agents show <id>` для 1–3 лучших (не больше трёх). Смотри:
   - первый промт — как директор сама ставит такие задачи: словарь, степень детальности, формат результата.
     Это образец стиля, а не текст для копирования;
   - «что человек дописал потом» — этого не хватило в первом промте. Добавь в новый промт сразу
     («смотри ещё файл X», «считай без НДС» — значит, нужен файл X и правило про НДС);
   - какие файлы читали и создали, чем кончилось.
3. **Источник задачи.** Задача из встречи — найди в расшифровке (`Grep` по `data/meetings/<id>/transcript.md`)
   место, где о ней говорили: дословная цитата и время `[чч:мм:сс]`, кто просил, какие условия прозвучали.
   Из сообщения — само сообщение и, если нужно, соседние (`./ops messages show <id>`).
   При нужде — `./ops projects show <id>`, `./ops kb search "<тема>"`, `./ops docs search "<слова>"` и
   `./ops docs show "<файл>" --part "…"`. Всего не больше 10 команд.
4. **Файлы** — только нужные задаче и только существующие, абсолютными путями; у каждого — зачем он агенту
   (что в нём, какой лист / слайд). Кандидаты из контекста бери с умом: файл из похожей сессии нужен,
   если новая задача про то же.
5. **Напиши промт** Write-ом в файл из шага 1 по шаблону ниже и сохрани:
   `./ops agents brief-save <номер поручения> --file <путь из шага 1>`. Команда скажет, каких файлов нет —
   поправь и сохрани ещё раз.

## Шаблон

```markdown
# Задача: <заголовок>
PULSE: задача #<id задачи>

## Что нужно получить
<результат и критерий готовности — что именно сдать и как понять, что готово>
Срок: ДД.ММ. Для кого: <кому обещано>.

## Контекст
- Откуда задача: встреча «…» ДД.ММ [чч:мм:сс] — «цитата»; сообщение в чате «…» ДД.ММ — «цитата».
- Проект «…»: зачем он и что в нём уже сделано (2–3 строки).
- Решения, которые нельзя нарушать: … (дата, источник).
- Ждём / нас ждут: …

## Файлы
- <абсолютный путь> — зачем (что в нём, какой лист / слайд)

## Как такое уже делали
- «<название сессии>» ДД.ММ: просили <суть первого промта>; использовали <файлы>; получилось <файлы / итог>.
  Пришлось уточнять: <что дописывали потом>.

## Как сделать
<шаги, если они понятны из похожих сессий; формат результата; куда положить файл — в папку проекта>

## Если неясно
<1–3 вопроса, которые стоит задать до начала, а не угадывать>
```

- Строка `PULSE: задача #<id>` — сразу под заголовком, всегда: по ней PULSE найдёт сессию агента.
- Раздел «Файлы» — строго строками `- <абсолютный путь> — зачем`: PULSE покажет их директору галочками.
- Пустые разделы удаляй. Длина — сколько нужно, обычно 20–60 строк.
- Только факты из источников. Чего нет в данных — так и пиши: «прогноза в данных нет — спроси».
- Пиши агенту на «ты», директора называй по имени из `./ops overview` или «директор»; внутренние
  номера PULSE (кроме служебной строки) не пиши.
- Агент — Codex: не упоминай навыки и инструменты Claude Code, проси читать файлы и работать в папке проекта.
- При пересборке начни с прошлого промта (в нём правки директора) и сделай то, о чём она просит.
- Личные (нерабочие) переписки не цитируй. Секреты, токены, пароли и пути в `secrets/` — никогда.
