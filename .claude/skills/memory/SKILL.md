# Память

Факт: одно утверждение о рабочем мире, которое пригодится директору **через месяц**. Это цифра, состояние, кто за
что отвечает, как работает человек или клиент, событие с датой, как что устроено. У каждого факта есть источник и
цитата. Факты пишутся пачкой: **один файл и одна команда `./ops facts import` на запуск**, потому что каждый лишний
вызов перечитывает весь контекст.

## Какие факты нужны

- **Виды.** `metric`: цифра с единицами и периодом. `state`: состояние («прайс на 2027 согласован»). `role`: кто за
  что отвечает. `trait`: как работает человек или клиент («Олег согласует договоры только письменно»). `event`: что
  случилось или назначено, с датой. `how`: как устроено («выгрузка остатков лежит в таблице „Склад-2027“»).
- **Понятен без источника:** кто или что, и что именно. «Конверсия 12%» плохо, «Конверсия в оплату у „Ромашки“ за
  октябрь: 12%» хорошо.
- **`about`**: о ком или о чём. Первым ставь того, чей это признак (у конверсии «Ромашки» это «Ромашка», а не Олег,
  который её назвал). Имена людей пиши как в `./ops people list`, сущности как в `./ops memory entities`.
  Новую сущность опиши в `entities` файла: вид (`person`, `company`, `product`, `project`, `metric`, `system`,
  `team`) и другие написания.
- **`key`** нужен цифрам и состояниям, которые изменятся: имя признака, понятное без факта («конверсия в оплату за
  месяц», «срок переезда склада»), а не «стадия» или «статус». Тот же ключ у первой сущности `about` сам сменит
  прежний факт, и директор увидит «было → стало». В блоке «Уже известно» ключи видны, используй их.
- **`because`** ставь, только если причина сказана прямо: это `ref` другого факта того же файла.
- **Не факт:** задачи и договорённости (их ведут разборы сообщений и встреч), решения (база знаний), оценки людей,
  кадровые дела конкретных людей (ставки, сокращения, увольнения, соглашения с HR, отпуска), биография и личное (в
  том числе самого директора), здоровье, семья, личные деньги, пароли и ключи, болтовня, шутки, разовые происшествия
  без последствий, то, что верно день-неделю («сегодня в офисе»), кто что сделал за день («Влад собрал презентацию»:
  это ход задачи, а не факт), предположения («вроде бы»). Не повторяй то, что уже есть в «Уже известно» и не
  поменялось.
- Лучше 5 точных фактов, чем 30 мелочей. Потолок 40 за запуск: больше `import` не запишет.

Файл:
```json
{"entities": [{"name": "Ромашка", "kind": "company", "aliases": ["ООО «Ромашка»", "РМШ"]}],
 "facts": [
  {"kind": "metric", "text": "Конверсия в оплату у «Ромашки» за октябрь — 12%", "key": "конверсия в оплату",
   "about": ["Ромашка"], "source": "telegram:4040", "quote": "конверсия в оплату за октябрь 12%"},
  {"kind": "trait", "text": "Олег согласует договоры только письменно", "about": ["Олег Петров"],
   "source": "pachca:4102", "quote": "согласую только по почте, устно не считается"}]}
```
Источник: `<источник>:<id сообщения>` (номер в квадратных скобках) или `meeting:<id>`. Цитата дословная и короткая.

## «Память дня» (задание memory-day)

1. `./ops memory day`: сообщения рабочих чатов за сегодня (или за `--date` из запроса). Наверху блок «Уже
   известно» о тех, кто в переписке, с ключами. Длинный день идёт частями (строка «Дальше: … --part 2» внизу),
   прочитай все части.
2. Выбери факты по правилам выше. Чатов «не запоминать» здесь нет, не ищи их.
3. Write `data/memory/day-<ГГГГ-ММ-ДД>.json`, затем `./ops facts import data/memory/day-<ГГГГ-ММ-ДД>.json`.
4. Прочитай подсказки в ответе `import`. «Похож на [ф12]»: если новый факт сменяет старый, вызови
   `./ops facts set <новый> --replaces 12`. «Новая сущность … похожие: …»: если это одно и то же, вызови
   `./ops memory merge <новая> --into "<старая>"` (дубль, записанный тобой сейчас) или добавь `--propose --reason "…"`
   (обе страницы давно есть, решит директор).
5. Директора не уведомляй: вечерний дайджест скажет, что узнано за день.

## Разовое наполнение (задание memory-backfill)

1. `./ops memory backfill --next 10`: следующие 10 разобранных встреч (id, дата, путь к summary.md).
2. Read каждый `summary.md` (только разбор, без расшифровки). Факты бери из разделов «Коротко», «Решения»,
   «Договорённости», «Связь с текущими задачами» по правилам выше. У каждого факта источник `meeting:<id>`, цитата
   (строка разбора с `[чч:мм:сс]`) и `when` (дата встречи). Из старой встречи бери только то, что могло остаться
   верным; события и цифры пиши с их датой. Встречу «Личная» пропусти.
3. Один файл на все 10: Write `data/memory/backfill.json`, затем `./ops facts import data/memory/backfill.json`.
4. `./ops memory backfill --done <id>,<id>,…` по всем 10, включая те, где фактов не нашлось.

## Выжимки страниц (задание memory-leads)

1. `./ops memory leads`: страницы, где набралось 10 новых фактов (не больше 20 самых живых).
2. По каждой вызови `./ops page "<имя>"` и напиши 5–8 строк «главное сейчас»: что это, в каком состоянии, последние
   изменения («было → стало»), что важно знать перед разговором. Пиши только то, что есть на странице, с датами «на
   ДД.ММ», без оценок людей.
3. Один файл: Write `data/memory/leads.json` в виде `{"<имя>": "<текст выжимки>", …}`, затем
   `./ops memory leads --set data/memory/leads.json`.

## Нельзя

Писать коллегам, создавать задачи и предложения карточек, менять задачи. Факт «от вас» (директора) не сменяй:
`import` сам превратит такую смену в предложение.
