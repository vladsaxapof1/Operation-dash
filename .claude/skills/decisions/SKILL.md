# Решения по темам: вопросы и цепочки

Директор видит тему так: строка «о чём тема», ниже — **вопросы** одной строкой: «Розница: веса тимлида — 35 / 12,5 /
12,5 / 40 — с 02.11», по клику — история (решили → поменяли → уточнили). Цель — чтобы это читалось за секунды. Список
решений без связей бесполезен: «Премия продаж — 80% всем» от 27.10 и «Премия — по ступенчатой шкале» от 30.10 — не два решения, а одно, которое
поменяли. Решения пишет разбор встреч (`./ops kb add --kind decision`) и импорт заметок из документов; здесь ты их
**связываешь и дополняешь** — ничего не придумывая, только по сути, подробностям, цитате и источнику.

## Шаги

1. **Темы.** `./ops decisions topics` — темы с подтемами (подтема — после « / »: «Логистика / Склад»).
   - Одна тема под разными названиями («Качество звонков» и «Контроль качества звонков», «Склад» и «Логистика / Склад») →
     `./ops decisions rename-topic "<лишнее название>" --to "<основное>"` (подтемы сохранятся). Основное — то, где
     решений больше, или общее для направления.
   - Решение не в своей теме → `./ops decisions set <id> --topic "<тема>[ / <подтема>]"`.
   - Тем не плоди: тема — направление работы («KPI», «Логистика»), а не одна встреча.
   - **О чём тема** — у каждой темы без описания (в `topics` — «о чём: не написано»):
     `./ops decisions about "<тема>" --text "<одна строка до 100 знаков>"` — что в ней решают, по существу:
     «KPI на ноябрь для команд продаж: цели, веса метрик, как считаем качество звонков». Без «в этой теме…».
2. **Цепочки — по каждой теме:** `./ops decisions topic "<тема>"` (сверху — что действует, ниже — уже собранные цепочки),
   подробности решения — `./ops decisions show <id>`. Найди решения **по одному вопросу** (одна метрика, одна воронка,
   одна роль, один документ) и свяжи каждое с ближайшим прежним:
   `./ops decisions set <новое> --prev <прежнее> --relation changes|refines|follows|cancels`
   - `changes` — **меняет**: было одно, стало другое («Премия продаж — 80% всем» → «Премия — по ступенчатой шкале»). Прежнее перестаёт действовать.
   - `cancels` — **отменяет**: решили не делать то, что решили раньше. Прежнее перестаёт действовать.
   - `refines` — **уточняет**: прежнее в силе, новое добавляет детали («Премия — по ступенчатой шкале» → «ступени 60 / 80 /
     100% по выполнению плана»).
   - `follows` — **продолжает**: следующий шаг того же решения («переходим на оплату по факту поставки» → «условия оплаты
     для поставщиков на ноябрь: …»).
   Связывай, только если вопрос действительно один; похожие слова — не повод. Прежнее — раньше по дате. Подсказки:
   в подробностях разбора встречи бывает «меняет решение от ДД.ММ» — это прямая связь; цифры той же метрики в разные
   даты — тоже. Решение из другой темы связать можно, если вопрос тот же.
3. **Вопрос и что решено** — у каждого решения без них (в `topic` у такой строки нет «вопроса» в кавычках или он
   взят из сути): `./ops decisions set <id> --question "<вопрос>" --answer "<что решено>"`
   - **Вопрос** — 2–4 слова, о чём решали: «Розница: веса тимлида», «Скидка на годовой тариф», «Цель конверсии триалов»,
     «Выбор CRM». Не решение и не глагол. У всех решений одной цепочки — **один и тот же** вопрос.
   - **Что решено** — что по вопросу действует **после этого решения**, коротко (до 100 знаков), без повтора вопроса,
     с цифрами: «35 / 12,5 / 12,5 / 40; маржа 40%», «Делаем сами, на AI-лупе; Twenty — только источник UX». У
     уточнения — итог целиком, а не одна добавка: строка последнего решения цепочки — это «Сейчас» вопроса.
   - Цифры, имена, сроки — как в источнике; ничего не добавляй от себя. Внутренние сокращения команды оставляй.
4. **Ждут решения.** Открытые вопросы (`./ops decisions list --stage discussing`): если в источнике прозвучал
   следующий шаг — кто что делает или чего ждём («посчитаю», «после встречи Олега с собственником», «итог — после пересчёта») —
   `./ops decisions set <id> --next "<кто и что, с датой, если прозвучала>"`. У принятого решения, которое ждёт
   условия, — тоже `--next`.
5. **Было → стало.** Только если цифры есть в сути, подробностях или цитате:
   `./ops decisions set <id> --metric "<что меняем>" --before "<было>" --after "<стало или цель>"`. Для `changes`
   «было» часто — цифра из прежнего решения цепочки.
6. **Задачи** — дополнительно: если открытая или закрытая задача исполняет решение («Внести 15 тыс. в калькулятор»),
   свяжи `./ops decisions link <id> --task <id задачи>`. Похоже, но не то — не связывай.
7. Отчёт не нужен: темы и вопросы директор видит в разделе «Решения», а что поменялось — в утреннем дайджесте.

## Правила

- Статус (принято / ждёт решения) не меняй, решения устаревшими не отмечай, задачи не создавай — это решает директор.
- Заполняй пустое. Связь с прежним, вопрос, «что решено» и «о чём», которые уже стоят, не меняй — их могла
  поставить или поправить директор. Исключение — вопрос у решения, которое ты только что связала с цепочкой: он
  должен совпасть с вопросом цепочки.
- Цепочка — от старого к новому, без кругов: у решения одно прежнее, у прежнего может быть несколько продолжений.
