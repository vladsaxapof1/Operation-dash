# Реестр решений

Цель — чтобы по каждому решению было видно: исполняется ли оно и чем. Решение без задачи через неделю — повод
директору спросить «кто этим занимается?». Решения пишет разбор встреч (`./ops kb add --kind decision`) и импорт
заметок-решений из документов; здесь ты их **связываешь с задачами** и **дополняешь** — ничего не придумывая.

## Шаги

1. **Без исполнения:** `./ops decisions list --orphan` — приняты больше недели назад, задач нет. Затем свежие:
   `./ops decisions list --stage decided --limit 60` — у них тоже могут быть задачи без связи и пустая метрика.
2. **По каждому** — `./ops decisions show <id>`: суть, подробности, цитата, источник (`meeting:<id>` — встреча,
   `document:<путь>` — документ).
3. **Задачи, которые его исполняют.** Ищи по смыслу, а не по словам один в один:
   - открытые и недавно закрытые: `./ops commitments list --status all` (видны источник и проект),
     по человеку — `./ops commitments list --person "<имя>" --status all`;
   - задачи той же встречи — первые кандидаты: в `summary.md` встречи раздел «Задачи» рядом с «Решениями»
     (`./ops meetings show <id>`);
   - Kaiten: `./ops kaiten cards --search "<слово>"` — карточка подтверждает, что работа идёт, но связать можно
     только задачу PULSE (у неё в строке видно `kaiten #…`).
   Задача исполняет решение, если её результат и есть то, что решили («Средний чек апсейла — 15 тыс.» →
   «Внести 15 тыс. в калькулятор KPI ОРК»). Связывай: `./ops decisions link <id> --task <id задачи>[,<id>]`.
   Похоже, но не то («обсудить чек» ≠ «внедрить чек») — не связывай.
4. **Было → стало.** Только если цифры или состояния есть в сути, подробностях или цитате:
   `./ops decisions set <id> --metric "<что меняем>" --before "<было>" --after "<стало или цель>"`.
   Метрика — коротко, по-человечески: «средний чек апсейла ОРК», «дозвон по МСБ», «срок ответа клиенту».
   Нет цифр — не придумывай; можно только метрику без «было».
5. **Ждёт.** Решение прямо зависит от чего-то («после согласования собственника», «когда будет MR 517») →
   `./ops decisions set <id> --stage waiting --waiting "<чего ждём, с датой, если прозвучала>"`.
6. Отчёт не нужен: реестр директор видит в разделе «Решения», а без исполнения — в утреннем дайджесте.

## Правила

- Только связи и поля реестра. Задачи не создавай, стадию «внедрено» не ставь, устаревшими не отмечай, стадию
  «обсуждается» не меняй — это решает директор.
- Связь, которую директор убрала, не возвращай: если задача уже связана с другим решением, не перевязывай её.
- Одно решение — несколько задач можно; у задачи — одно решение.
