# Уроки из ваших «Нет»

Цель — чтобы PULSE перестал предлагать то, что директор раз за разом отклоняет. Каждое «Нет» — сигнал, но один
отказ ещё не закономерность. Ищи **повторы**: одно и то же предложение по одной и той же причине. Из повтора
получается правило для навыка, который эти предложения делает. Правило — обычными словами, как директор сказала бы
помощнику сама. Включится оно только после её «Да» и попадёт в «Ваши правила» навыка (Навыки → навык).

## Шаги

1. **Что отклоняли:** `./ops proposals rejected --days 14`. У каждого — тип, заголовок, почему предлагали и почему
   «Нет»: «не задача», «уже есть», «не тому», «не сейчас», «другое — …». Причину указывают не всегда.
2. **Какие правила уже есть:** `./ops skills list`, по нужным навыкам — `./ops skills rules <навык>`. Не предлагай то,
   что уже действует, и то, что противоречит её правилам.
3. **Повторы.** Сгруппируй отказы: тот же тип предложения и та же причина, плюс общий признак — та же серия встреч
   («Daily …», «1:1 с …»), тот же чат или отправитель, тот же человек, тот же вид сообщений (рассылки, уведомления
   сервисов, статусы без поручений). Закономерность — **три и больше** похожих отказа, или два с одной и той же
   причиной, если признак очевиден. Без указанной причины выводи её из заголовка и «почему предлагали» осторожно.
4. **Чей навык.** По типу предложения и источнику (`source_ref`):
   - `task.meeting`, `task.done`, `task.log`, `attention.done`, `telegram.remind`, `kaiten.*` из переписки (`telegram:`, `pachca:`,
     `mail:`, `ymessenger:`) → `triage`;
   - то же из встречи (`meeting:`) → `process-meeting`;
   - напоминания коллегам из дайджеста → `digest`;
   - `project.create`, `task.wait`, `task.merge` → `projects`;
   - карточки и встречи из ответов в боте → `ask`, из «Спросить» → `chat`.
5. **Правило.** Конкретное, про одно, в повелительном наклонении, с признаком, по которому навык его применит:
   - хорошо: «Не предлагай связывать задачи со встречами серии „Daily Автоворонки“ — это общий статус, а не встреча
     по задаче»; «Рассылки и уведомления сервисов (noreply, „Ваш заказ“) не разбирай как поручения»; «Не предлагай
     напоминать коллеге, если срок задачи прошёл меньше суток назад»;
   - плохо: «Будь внимательнее», «Не ошибайся», «Предлагай меньше» — навык не поймёт, что делать иначе.
   Правило не может разрешать то, что запрещает CLAUDE.md: внешние действия — только предложениями.
6. **Предложи** (не больше трёх правил за раз, самые частые повторы первыми):
   `./ops propose rule --skill <навык> --text "<правило>" --reason "<повтор: сколько отказов и с какой причиной>" --quote "<номера отказов: [12] заголовок — причина; [15] …>" --batch lessons:<ГГГГ-ММ-ДД>`
   Если команда ответила, что такое правило уже есть или его уже отклоняли, — не переформулируй его, чтобы обойти.
7. **Сообщи** одним сообщением, если предложила хоть одно правило:
   `./ops notify "<b>Уроки из ваших «Нет»</b>\n<что повторялось — 1–3 строки человеческим языком>" --batch lessons:<ГГГГ-ММ-ДД>`
   Кнопки «Да / Нет» у правил приложатся сами. Повторов нет — ничего не отправляй и не придумывай правила.

## Правила

- Сама правила не включай и не меняй — только предлагай. Решение — за директором.
- Тексты для директора — без внутренних номеров и типов (`task.meeting`, `[12]`): «связи задач со встречами»,
  «напоминания Петрову». Номера — только в `--quote`, там их видно по ссылке.
- Личное (здоровье, семья) из отклонённых заголовков не пересказывай.
