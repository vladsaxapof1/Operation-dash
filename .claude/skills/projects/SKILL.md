# Сборка проектов

Цель — чтобы по каждому большому делу директора было видно: что уже сделано, что можно делать сейчас,
что ждёт других и на ком всё стоит. Проект — это не тема и не человек, а **результат**, к которому ведут
несколько задач: «Запуск склада в Казани» (схемы Дмитрия → ответы на вопросы → описание
подрядчику → схемы в карточку проекта), «Регламент продаж на ноябрь», «Бюджет 2027».

## Шаги

1. **Что уже есть:** `./ops projects list --all`, у каждого активного — `./ops projects show <id>`.
2. **Задачи:** `./ops commitments list` (открытые) и `./ops commitments list --status done` (недавно закрытые —
   они тоже часть проектов и дают прогресс). В строке видно проект, связи «ждёт», «её ждут», подзадачи.
3. **Контекст** — только чтобы понять, что с чем связано (по одной команде, без конвейеров):
   - `./ops meetings list --days 14`, затем `summary.md` встреч, где обсуждали эти задачи
     (разделы «Задачи», «Связь с текущими задачами», «Открытые вопросы»);
   - `./ops messages search "<тема>"` — переписка вокруг задачи («как будет готово — кидай»,
     «без папки не отдам», «сначала схемы, потом описание»);
   - `./ops kaiten cards --search "<слово>"` — карточки рабочей группы по той же теме;
   - `./ops kb search "<тема>"` — решения, которые объясняют, зачем всё это.
4. **Проекты.**
   - Новый — если **три и больше** задачи (открытые и недавно закрытые) ведут к одному результату и он
     не помещается в одну задачу. Название — результат, 2–6 слов, по-человечески; `--goal` — что считаем
     готовым; `--due` — только если срок прозвучал. Подзадачи указывать не нужно — пойдут за основной.
     `./ops propose project --title "…" --goal "…" --tasks 57,69,80,92 --reason "<что их объединяет, со ссылкой на встречу или переписку>" --source <откуда> --batch projects:<ГГГГ-ММ-ДД>`
   - Уже есть подходящий проект, а задача в нём не числится → `./ops commitments set <id> --project <id проекта>`
     (сразу, без предложения). Задачу, которую директор уже положила в другой проект, не перекладывай.
   - Не проект: «разное с Петром», «всё про KPI» без общего результата, одна задача с подзадачами
     (для этого есть подзадачи), разовые мелочи.
5. **Связи внутри проекта** — по правилам из CLAUDE.md («Ждёт», «Дубль»):
   - прямо прозвучало «без X не сделать Y» → `./ops commitments wait <Y> --for <X> --note "…" --source …`;
   - понятно только по смыслу → `./ops propose wait --commitment <Y> --for <X> --reason "…" --batch projects:<ГГГГ-ММ-ДД>`;
   - ждёт событие («после встречи с собственником», «когда пришлют остатки») → `wait <id> --event "…" --until YYYY-MM-DD`;
   - одно и то же записано дважды (одна работа, разные слова, тот же человек) →
     `./ops propose merge --commitment <дубль> --into <основная> --reason "…" --quote "…" --batch projects:<ГГГГ-ММ-ДД>`.
     Оставляй ту, у которой точнее суть, срок и источник; закрытую в открытую — можно, наоборот — нет.
   - по переписке или встрече задача уже сделана → `./ops propose done …` (как в навыке triage);
   - большая задача из названных частей без пунктов → `./ops commitments items <id> --add "…; …"`, готовые части
     по переписке — `--done "…" --note "…"`: тогда процент проекта честный;
   - у задачи, которая ждёт, и у той, что ждут, есть карточки Kaiten, а в Kaiten блокировки нет (в строке задачи
     нет «в Kaiten») → `./ops propose kaiten-block --card <id> --blocker-card <id> --reason "…" --batch projects:<ГГГГ-ММ-ДД>`.
6. **Не больше** 5 новых проектов и 15 предложений за раз — самое важное. Команда ответила «уже ответила
   «Нет»» — не повторяй.
7. **Уведоми,** только если что-то предложил или поменял:
   `./ops notify --kind info --batch projects:<ГГГГ-ММ-ДД> "<b>Проекты</b>\n<по строке на проект: название — что предлагаю и почему>"`
   Например: «Запуск склада — 9 задач, стоит на Дмитрии (схемы возвратов и инвентаризации); «Процессы по карте
   склада» — дубль «Схемы процессов склада»».

Не придумывай связей: каждая — с источником (встреча, сообщение, карточка) или с понятным из текста задач
доводом. Личные и нерабочие переписки не берём. Последней строкой ответа — сколько проектов и предложений.
